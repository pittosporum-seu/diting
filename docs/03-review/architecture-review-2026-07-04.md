# 谛听 · 架构审查报告

> 审查日期：2026-07-04 | 审查版本：v1.0 → v2.0

---

## 审查结论

**v1.0 架构方向正确，三条核心原则（单向依赖、分层解耦、降级容错）落地良好。** 以下问题在 v2.0 中已修复：

### 已修复

| # | v1.0 问题 | v2.0 方案 |
|---|----------|----------|
| 1 | 模块通讯隐式约定（DataFrame列名靠猜） | 全套 @dataclass schema，接收方不用猜 |
| 2 | 模块化不够开闭（加引擎改main.py） | 插件注册制 @register_engine |
| 3 | 接口抽象不均匀（Wyckoff/Buffett 无共同基类） | AnalysisEngine ABC 统一接口 |
| 4 | 缓存层缺失（每次全量拉数据） | CacheLayer + @cached 装饰器 |
| 5 | 零可观测性（靠print调试） | structlog 结构化日志 |
| 6 | L0/L1/L2 切换逻辑模糊 | DITING_LEVEL 环境变量 + Command模式 |
| 7 | 测试策略空白 | 分层测试策略（L0>90%, L4>50%） |

### v2.0 新增

| 新增 | 说明 |
|------|------|
| Python 沙箱 | AI 生成计算代码→沙箱执行，可审计、防幻觉 |
| 多引擎共识 | 冲突检测 + 加权融合 + 置信度评分 |
| 事件告警 | Observer 模式，RSI<20/VMD谷底/大盘暴跌自动推送 |
| 管道配置 YAML | 非开发人员可调整策略参数 |

### 待评估

- nanoagent / AI 编排：适合放在上层（Hermes Agent skill 层），谛听核心库保持确定性管道
- Web UI：待 v1.0 发布后评估
