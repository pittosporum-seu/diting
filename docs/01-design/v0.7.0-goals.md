## 一、核心目标

**所有分析在本地能完整跑通，数据时效性可见，失败有反馈。**

## 二、改进方向

### 2.1 数据时效性

用户打开页面时，应该清楚地知道「这个数据是什么时候的」。不能猜。不能靠前端缓存时间，应该由后端告诉前端。

- 所有 API 响应含服务端时间戳
- 所有 Web 页面显眼位置标注数据时间
- 缓存过期时标注「数据可能滞后」

### 2.2 缓存策略

现在的缓存（固定 5 分钟 TTL）不区分交易状态。应该按 MarketState 分层：

- 交易时段：高频刷新（30s-1min）
- 午休/盘后/周末：不调 API，返回已有数据
- 任何时候：有数据就先显示，不转圈等 API

### 2.3 错误处理

现在后台刷新失败时静默保持旧数据，用户不知道。应该：

- 刷新失败 → 保留旧数据 + 显示轻量提示
- 完全无数据 + API 失败 → 显示错误卡片

### 2.4 前后端协作

现在前端的缓存逻辑（SWR）和后端的数据提供逻辑有重叠。思考：

- 数据该由谁缓存？（前端 localStorage？后端 SQLite？L1 内存？）
- 时间戳由谁提供？
- 刷新策略该由前端还是后端控制？

### 2.5 代码组织

检查现在的分层是否合理。关注：

- 业务逻辑是否都正确分层了？（routes vs services vs data providers）
- 有没有跨层依赖？
- 测试覆盖率够不够？
