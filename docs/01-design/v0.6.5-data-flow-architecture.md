# v0.6.5 — 数据流架构：Market-Aware Cache-First

> 基于海桐 2026-07-12 讨论 | 核心：**用户点击时数据已经是热的**

## 一、问题

### 1.1 现状

当前数据流：
```
用户点击 →
  L1 内存 TTL (命中→返回，未命中→L2)
    → L2 SQLite (命中→返回+异步API，未命中→调API)
      → API (mx-data/ashare)
```

**三个问题：**

1. **不知道市场状态**——周末也一样去调 API，TTL 过期了就得重拉，周末拉也白拉
2. **用户点的时候数据不是热的**——如果用户 5 分钟没操作，TTL 过期了，再点就要等
3. **前台首次加载白屏**——即使 DB 有数据，也等着走完 L1→L2→API 才渲染

### 1.2 目标

- **用户点击时数据早已热好**（后台每 5 分钟预刷新）
- **非交易时段零 API 调用**（感知市场状态，只读 DB）
- **前台 0ms 白屏**（DB 数据先渲染，后台静默更新）

## 二、核心设计

### 2.1 MarketState — 市场状态判断模块

新增 `src/diting/cache/market_state.py`。

#### 三种主状态

| 状态 | 含义 | 行为 |
|------|------|------|
| `TRADING` | 盘中（交易日 9:30-11:30, 13:00-15:00） | 正常缓存+后台刷新+调API |
| `CLOSED` | 非交易时段（含午休/盘前/盘后） | DB数据够用，不调API，prefetch跳过 |
| `WEEKEND` | 非交易日（周末/法定节假日） | 永不调API，prefetch跳过 |

**时间线（以交易日为例）：**

```
00:00 ───────── 09:30 ──── 11:30 ──── 13:00 ──── 15:00 ──────── 24:00
  │  CLOSED  │ TRADING │ CLOSED  │ TRADING │       CLOSED       │
  │          │         │ (午休)  │         │                    │
  │ 不调API  │ 正常    │ 不调API │ 正常    │     不调API         │
  │ prefetch │         │ prefetch│         │     prefetch        │
  │  跳过    │         │  跳过   │         │      跳过           │
```

#### MarketState 数据结构

```python
@dataclass
class MarketState:
    phase: Literal["trading", "closed", "weekend"]
    last_trade_date: date      # 上一个交易日
    next_trade_date: date      # 下一个交易日
    today_is_trade_day: bool   # 今天是不是交易日
    next_open_time: datetime | None  # 下次开盘时间（用于倒计时等）
```

#### 交易日历判断逻辑（优先级）

1. 查内置法定假日白名单 → 命中则 WEEKEND
2. 查调休上班日白名单 → 命中则按交易日处理
3. 周六/周日 → WEEKEND，除非被白名单覆盖为调休上班
4. 周一~周五 → 交易日
5. 交易日判断当前时间 → 9:30-11:30 或 13:00-15:00 → TRADING，其余 → CLOSED

#### 2026 法定假日白名单（内置）

| 假日 | 日期 | 天 | 调休上班 |
|:-----|:----:|:::|:--------|
| 元旦 | 01-01 ~ 01-03 | 3 | — |
| 春节 | 02-15 ~ 02-21 | 7 | 02-14(六)、02-22(日)上班 |
| 清明 | 04-04 ~ 04-06 | 3 | — |
| 劳动节 | 05-01 ~ 05-05 | 5 | 04-26(日)、05-09(六)上班 |
| 端午 | 06-25 ~ 06-27 | 3 | — |
| 中秋+国庆 | 09-26 ~ 10-04 | 9 | 09-19(六)、10-10(六)上班 |

> 节假日数据维护在 `CONFIG_HOLIDAYS` 和 `CONFIG_MAKEUP_DAYS` 两个常量中，每年更新一次即可。

### 2.2 Background Prefetch — 定时预刷新

#### 行为规则

| 状态 | Prefetch 行为 | 原因 |
|:-----|:-------------|:-----|
| `TRADING` | ✅ 每 5 分钟：拉 dashboard/watchlist/opportunities/sentiment | 价格在变 |
| `CLOSED` | ❌ 跳过，不调任何 API | 市场没开，数据不会变 |
| `WEEKEND` | ❌ 跳过，不调任何 API | 非交易日 |

#### 实现方式

```python
import threading
import time

class BackgroundPrefetcher:
    """后台预刷新线程。AnalysisService 启动时调用 start()。"""

    def __init__(self, service: AnalysisService):
        self._service = service
        self._running = False
        self._thread: threading.Thread | None = None
        self._lock = threading.Lock()      # 防重叠

    def start(self):
        self._running = True
        self._thread = threading.Thread(target=self._loop, daemon=True)
        self._thread.start()

    def stop(self):
        self._running = False

    def _loop(self):
        while self._running:
            time.sleep(300)  # 5分钟
            # 防重叠：上一次还没跑完就跳过本轮
            if not self._lock.acquire(blocking=False):
                continue
            try:
                self._refresh()
            finally:
                self._lock.release()

    def _refresh(self):
        state = get_market_state()
        if state.phase != "trading":
            return  # 非交易时段跳过

        svc = self._service
        # 静默刷新——不抛异常、不重试
        try:
            svc.get_dashboard_data(force_refresh=True)
        except Exception:
            pass
        try:
            svc.get_watchlist(force_refresh=True)
        except Exception:
            pass
        try:
            svc.get_opportunities(force_refresh=True)
        except Exception:
            pass
        try:
            svc.get_market_sentiment(force_refresh=True)
        except Exception:
            pass
        # force_refresh=True 的 API 调用失败时静默处理
        # DB 已有数据，不影响用户看到的内容
```

**Prefetch API 失败处理：** 某个 get 方法抛异常 → catch 住、记一行日志、跳过该数据。不影响其他数据，不影响用户。不会因为这个失败反复重试。

**首个 5 分钟间隙：** 应用刚启动，prefetch 还没跑过。用户打开页面时 L1 为空，L2 有旧数据 → DB 数据先渲染。5 分钟后 prefetch 跑一次，L1 热了。第二次点击就 <1ms。

### 2.3 Services 改造 — 三阶数据流

每个 `get_*()` 方法统一改造：

```python
def get_dashboard_data(self, force_refresh: bool = False) -> dict:
    # 1. force_refresh 时跳过缓存
    if not force_refresh:
        # L1: 内存 TTL
        cached = _dashboard_cache.get("_dashboard")
        if cached is not None:
            return cached

        # L2: SQLite
        try:
            cm = self._get_cache_mgr()
            db_row = cm.db_get("dashboard_cache", "1")
            if db_row and db_row.get("data_json"):
                result = json.loads(db_row["data_json"])
                _dashboard_cache.set("_dashboard", result)  # 补回 L1
                return result
        except Exception:
            pass

    # 3. 读缓存阶段已结束——要不要调 API？
    state = get_market_state()
    if state.phase != "trading":
        # 非交易时段：返回空/错误结果，不调 API
        return get_default_dashboard()

    # 4. TRADING 状态才调 API
    try:
        result = self._fetch_dashboard_from_api()
        _dashboard_cache.set("_dashboard", result)
        self._get_cache_mgr().db_set("dashboard_cache", "1", {...})
        return result
    except Exception:
        # API 失败时，如果 L2 有数据就返回旧的
        if cached_from_db := get_l2_data():
            return json.loads(cached_from_db["data_json"])
        return get_default_dashboard()
```

关键改动：
- **`force_refresh` 参数**：prefetch 传 True，跳过 L1/L2 直接调 API；用户正常请求传 False
- **L2 补 L1**：L2 命中时写入 L1，下次 L1 直接命中
- **MarketState 守卫**：非交易时段不调 API
- **API 失败回退**：调 API 失败但 L2 有数据 → 返回旧数据（graceful degradation）

### 2.4 完整数据流

```
                  ┌─────────────────────────┐
                  │ BackgroundPrefetcher     │
                  │ 每 5 分钟 (TRADING only) │
                  │ force_refresh=True        │
                  │ 跳过 weekend/closed       │
                  └───────────┬─────────────┘
                              │ 写入 L1 + L2
                              ▼
┌─────────┐   读取   ┌──────────────┐     L2 read    ┌──────────┐
│ 用户点击  │ ───────→ │  L1: 内存TTL  │ ←────────── │ L2: SQLite│
│          │          │  (热层)      │               │  (冷层)   │
│          │          │  <1ms       │               │           │
└────┬─────┘          └──────┬───────┘               └─────┬─────┘
     │                       │ miss                        │ miss
     │                       ▼                             ▼
     │                ┌──────────────┐             ┌──────────┐
     │                │ MarketState  │             │ 数据源API │
     │                │ 判断是否调API │ ←──────── │ mx-data   │
     │                │              │ 仅 TRADING │ ashares   │
     │                │ CLOSED→不调  │             │           │
     │                │ WEEKEND→不调 │             └──────────┘
     │                └──────┬───────┘
     │                       │
     ▼                       ▼
┌──────────────────────────────────────┐
│  前台渲染                             │
│                                      │
│  Phase 1: 同步渲染（DB数据 / 骨架屏） │
│    - L1 命中 → 直接渲染              │
│    - L1 miss + L2 有 → DB数据显示    │
│    - 都 miss → 骨架屏                │
│                                      │
│  Phase 2: 后台静默更新               │
│    - 如果 Phase1 用的是 DB 旧数据     │
│    - TRADING → 调 API 拉最新的       │
│    - 有新数据 → 无缝替换（不闪屏）    │
└──────────────────────────────────────┘
```
