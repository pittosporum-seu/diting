# 个股分析全链路审计

> 逐一对照：代码逻辑 → 服务器日志 → 用户感知

---

## 问题 1: L2 缓存读取失败

**日志：**
```
cache.db_get.failed error='not enough values to unpack (expected 2, got 1)'
key=002475 table=stock_analysis_cache
```

**根因：** `stock_analysis_cache` 表是旧版结构（只有 2 列），但 `cache_manager.py:db_get()` 尝试用新结构（多列）解包，列数不匹配导致抛异常。

**用户感知：** 每次看个股都是 cache miss，AI 引擎全跑一遍，等 30-60 秒。

**预期行为：** L2 缓存读取失败不应影响用户，应 fallback 到旧数据或自动修复表结构。

---

## 问题 2: 周末没跳过 AI 引擎

**日志：**
```
ai.completion.done duration_ms=56986  (57s)
ai.completion.done duration_ms=37856  (38s)
ai.completion.done duration_ms=9843   (10s)
```

**根因：** `analyze_stock()` 没有 MarketState 守卫。周末缓存空的时候一样调 DeepSeek API。

**用户感知：** 周末打开个股分析，页面空白转圈 1 分钟。

**预期行为：** 周末跳过 AI 引擎，只返回技术指标（RSI/MACD/VMD）。有缓存直接显示。

---

## 问题 3: 网络连接失败

**可能根因：** 服务器在硅谷，调 DeepSeek API 可能超时。AI 引擎（wyckoff/buffett/can_slim）各请求一次 DeepSeek，总耗时 30-105 秒。

**用户感知：** 页面卡住，最后显示网络错误。

**预期行为：**
- 非交易时段不调 AI 引擎（根本不会触发网络请求）
- AI 引擎有超时保护（当前是 60s，可能在临界值）
- 超时后返回技术分析，不抛错误

---

## 问题 4: 前端没有缓存优先

**日志：** 前端直接发请求等后端返回，没有先显示缓存数据。

**根因：** `frontend/js/app.js` 的个股分析页没有用 SWR 模式。

**预期行为：** 先显示本地缓存/上次结果，后台静默刷新。

---

## 修复方案

### P0 — 修复 L2 缓存读取（立即生效）
`cache_manager.py` 的 `db_get()` 在列数不匹配时，返回 None 而不是抛异常。同时 `analyze_stock()` 在 L2 失败时继续走流程，不阻塞。

### P0 — 添加 MarketState 守卫
`analyze_stock()` 开头加：
```python
state = get_market_state()
if not state.should_call_api:
    # 非交易时段：跳过 AI 引擎，返回技术分析
    engine_names = [en for en in engine_names if en not in _ai_engines]
```

### P1 — AI 引擎超时保护
每个 AI 引擎调用设超时 30s，超时跳过该引擎。

### P2 — 前端缓存优先
个股分析页用 SWR 模式：先显示缓存数据，后台刷新。
